# แก้ไข frontend ตรงไหน

## โครงสร้าง

- `app/` เก็บ URL และเรียก page จาก features เท่านั้น
- `dashboard/` เมนูด้านซ้ายและภาพรวม
- `project/pages/` รายการงาน รายละเอียดงาน และบิล
- `project/components/` แท็บราคา วัสดุ ทีม นัดหมาย การเงิน และขั้นตอนงาน
- `project/types.ts` รูปแบบข้อมูล
- `project/data/mock-projects.ts` แก้งานตัวอย่าง ข้อมูลลูกค้าของงาน และเงินมัดจำ
- `project/data/mock-materials.ts` แก้รายการวัสดุตัวอย่าง
- `employee/data/mock-employees.ts` แก้รายชื่อพนักงาน
- `appointment/data/mock-appointments.ts` แก้นัดหมายตัวอย่าง
- `project/mock-data.ts` รวมข้อมูลจากไฟล์ข้างต้นให้ provider ใช้
- `project/project-utils.ts` สูตรราคา การชำระเงิน และเงื่อนไขเปลี่ยนสถานะ
- `project/project-provider.tsx` อ่าน/บันทึกข้อมูลใน localStorage จุดนี้ใช้เปลี่ยนเป็น API ภายหลัง
- `appointment/`, `employee/`, `payment/` หน้าสรุปแต่ละเรื่อง
- `shared/ui.tsx` ส่วนหน้าจอเล็ก ๆ ที่ใช้ร่วมกัน
- `app/globals.css` สีและ responsive layout

## เปิดใช้งาน

จากโฟลเดอร์ rubmaotest: `npm run dev` แล้วเปิด http://localhost:3000

## ขอบเขต

ใช้ CRUD_UseCase.xlsx ล่าสุด ไม่มี Stock และไม่มีหน้าจัดการลูกค้า
ข้อมูลใหม่มาจากส่วนลูกค้า/LINE OA ของอีกทีม เวอร์ชันนี้ใช้ mock-data.ts แทน
สถานะงานกับเงินแยกกัน งานปิดได้เมื่อ accepted และรับเงินครบ
รับที่ร้าน/ติดตั้งเลือกหลัง shop_passed แล้วนัดวันเวลา
ช่องประเภทนัดแสดงดูหน้างาน ติดตั้งหน้างาน และรับที่ร้านครบทุกตัวเลือก หัวหน้าเลือกได้เองทั้งตอนเพิ่มและแก้ไขนัด โดยไม่กรองตามสถานะงานหรือวิธีรับงาน
ไม่มีสถานะ working เพิ่มจาก Excel: confirmed ครอบคลุมเตรียมและทำงานที่ร้าน
ใบเสนอราคาเก็บ snapshot เพื่อให้ราคาที่ตกลงไว้แยกจากยอดจัดซื้อ

## อัปเดตยอดวัสดุ / จัดซื้อ

หัวหน้ากรอกยอดสะสม `acquired_quantity` ใน `Project.materials` ของแต่ละรายการ
จำนวนที่วางไว้ใช้จาก `Project.quotation.materials.quantity`
จำนวนที่ต้องซื้อเพิ่ม = max(จำนวนที่วางไว้ - acquired_quantity, 0)
ข้อมูลเดิมที่ยังไม่มี acquired_quantity จะเริ่มที่ 0 จึงใช้ localStorage เดิมได้
เพิ่มฟิลด์นี้ตามคำสั่งล่าสุดของผู้ใช้ แม้ Use Case Excel ยังไม่มีฟิลด์จัดซื้อ
การบันทึกยอดจัดซื้อไม่แก้ราคาบิล และไม่ใช่คลัง Stock
ไม่มีฟอร์มหรือปุ่มบันทึกวัสดุใช้จริงตามคำสั่งล่าสุดของผู้ใช้

## ลิงก์บิล

`/project/02/bill` มีปุ่มคัดลอกลิงก์และพิมพ์ PDF ไม่มีเมนูเจ้าของร้าน
แก้ข้อมูลแล้วเปิดลิงก์จากเบราว์เซอร์เดิมได้ แต่การส่งข้อมูลล่าสุดให้ลูกค้าข้ามเครื่อง
ต้องเปลี่ยน provider เป็น API ที่เก็บข้อมูลร่วมกันก่อน หน้า bill จะอ่านเฉพาะข้อมูลที่เปิดเผยได้
localStorage เป็นข้อมูลทดลอง ไม่ใช่ระบบสิทธิ์ผู้ใช้หรือฐานข้อมูลจริง
หลักฐานชำระเงินเป็นข้อความ/เลขอ้างอิงในเวอร์ชันนี้ ยังไม่มีการอัปโหลดไฟล์

## ล้างข้อมูลทดลอง

ลบ key `rubmao-demo-v1` ใน localStorage ผ่าน Developer Tools แล้วรีโหลด
เมื่อแก้ไฟล์ mock แล้วหน้าเว็บยังแสดงข้อมูลเดิม ให้ลบ key นี้ก่อน เพราะข้อมูลที่บันทึกในเบราว์เซอร์มีลำดับความสำคัญเหนือข้อมูลตั้งต้น

## ตรวจสอบ

ใช้ `npm run lint` และ `npm run build` ไม่มี automated tests ตามที่ผู้ใช้กำหนด
